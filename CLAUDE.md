# AIEng-MCPServer

## What we are building

The project has two phases:

1. **Product backend**: a simple Spring Boot REST service with CRUD on `Product`. Anyone can create, read and update products. Only users with the `ADMIN` role can delete one.
2. **Product MCP server**: a separate Spring AI MCP server that exposes the backend's Product APIs as MCP tools. It calls the running backend over HTTP, so an AI client (Claude Code or Claude Desktop) can manage products.

## Development approach: SDD (Spec-Driven Development)

Docs come before code. The order is:

`CLAUDE.md` → `docs/requirements.md` → for each module, `docs/modules/<module>/spec.md` → `test.md` → `plan.md` → implementation (tests first).

Rules:
- Each doc gets its own commit.
- No code is written without an approved spec. If a spec gap shows up while coding, stop, update spec.md/test.md, commit, then go back to the code.
- Every test references its `test.md` ID (e.g. `PRODUCT-T03`) in its name or a comment.
- Don't invent requirements. Ask the user one question at a time, with 4 options and the recommended one first.
- Requirement IDs: `FR-<area>-NN`, `NFR-NN`, `EC-NN`, `AC-NN`. Spec rules: `<MODULE>-SNN`. Tests: `<MODULE>-TNN`.
- Every doc ends with a **Decision log** table.

## Modules (build in this order)

| # | Module | Responsibility |
|---|--------|----------------|
| 1 | `product` | Product entity, JPA repository, service, REST controller (`/api/products`), validation, error responses |
| 2 | `security` | Spring Security HTTP Basic, in-memory users, `ADMIN` required only for `DELETE /api/products/{id}` |
| 3 | `mcp-server` | Separate Spring AI MCP server (stdio) exposing the Product APIs as MCP tools via `RestClient` |

## Tech stack

- Java 21 (the machine has JDK 25 installed, and the build targets release 21)
- Spring Boot 3.5.x, Maven multi-module build with the Maven wrapper (`mvnw`); no global Maven is installed
  - `product-backend/`: Spring Web, Spring Data JPA, H2 (in-memory), Bean Validation, Spring Security
  - `product-mcp-server/`: Spring AI MCP Server starter (stdio transport), `RestClient`
- Tests: JUnit 5, Spring Boot Test, MockMvc, spring-security-test
- Build/test command: `./mvnw test` (Windows: `mvnw.cmd test`) from the repo root

## Domain decisions

- **Product fields:** `id` (Long, generated by the server), `name` (required, max 100), `description` (optional, max 500), `price` (BigDecimal, required, > 0), `quantity` (Integer, required, >= 0).
- **Endpoints (5):**
  - `POST /api/products`
  - `GET /api/products` (list all, not paginated)
  - `GET /api/products/{id}`
  - `PUT /api/products/{id}`
  - `DELETE /api/products/{id}` (ADMIN only)
- **Auth:** HTTP Basic with in-memory users `admin/admin123` (ADMIN) and `user/user123` (USER). Every endpoint except DELETE is open to anyone, including unauthenticated callers.
- **Storage:** H2 in-memory with Spring Data JPA. Data resets on restart.
- **MCP server:** a separate Maven module. It calls the backend over HTTP and sends Basic credentials from configuration.

## Git workflow

- Local git repo, committing directly to `main`, with no remote yet. Push once a remote is added.
- Conventional commits: `docs:`, `docs(<module>):`, `test(<module>):`, `feat(<module>):`, `chore:`.
- Never commit `.idea/`, `target/`, `*.iml` or secrets.

## Sessions and conversation logs

- Each working session is numbered (`session-NN-<topic>`). At the end of a session:
  `node tools/export-session.mjs session-NN-<topic>`, then commit `chore(sessions): add session NN conversation log`.
- Session 01: SDD project setup.

## Working with the user

- Ask gap questions one at a time, with exactly 4 options and the recommended one first.
- List conventions you decided without asking, so the user can veto them.
- Do one SDD step per session unless the user asks for more.
